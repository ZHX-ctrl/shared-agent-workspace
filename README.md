# Shared Agent Workspace / 共享项目工作台

一个运行在本机的网页工作台，让 Codex CLI 与 Claude Code 共用项目文件夹、管理多条聊天，并在切换助手时交接可见记录和项目进度。

## 可以做什么

- 一个项目包含多条聊天；不同聊天共享项目文件，分别保存对话和原生会话关联。
- 通过已登录的官方 CLI 运行 Codex 或 Claude Code，支持流式回复、审批、停止、续接和按子目录分工协作。
- 切换助手时提供工作台可见历史、交接资料及同一个项目目录；较长历史按需读取，不传递内部推理，也不保证每轮将全部历史放进上下文。
- 提供文件夹选择、附件、聊天搜索、项目文件预览、技能目录、可用模型与额度显示。技能／应用附件和计划模式目前仅接通 Codex。
- 可选地向 Codex 桌面登记项目，在 Claude 桌面打开同一个文件夹或续接工作台绑定的原生会话。
- 在工作台操作一次，归档、恢复或删除已关联的 Codex／Claude 桌面聊天，无需退出桌面软件或再手动操作一遍。

工作台后台由 CLI 独立运行，关闭官方桌面不影响普通 CLI 聊天。需要同步桌面入口时，对应桌面窗口必须可用。官方软件里直接发送的新消息不会自动完整回传工作台时间线；需要两位助手接力时，主要在工作台记录进度。

## 安装与启动

已验收环境为 **Windows 10/11 x64、Node.js 24**，以及已安装并登录的官方 Codex CLI／Claude Code。Claude 桌面入口要求官方 Claude 桌面与 Claude Code CLI 2.1.285 或以上；实际验收 CLI 为 2.1.303。其他操作系统没有完成整体运行验收。本仓库不提供模型账号、CLI 二进制或 API 密钥。

1. 安装希望使用的官方 CLI，并在官方工具里完成订阅登录。工作台只接受已确认的订阅认证，不自动切换到 API 密钥计费。Claude 的 Extra usage／额外用量由账户设置控制；只使用订阅内额度时，应在官网关闭它。
2. 下载本仓库或克隆源码，在仓库文件夹打开 PowerShell，安装锁定的依赖：

   ```powershell
   npm ci --ignore-scripts --omit=optional --no-audit --no-fund
   ```

   依赖包括官方 Claude Agent SDK 和 Microsoft `node-pty`。SDK 用于本机会话管理；模型任务仍交给已登录的 CLI。安装禁用脚本，Windows 使用依赖随包提供的组件。

3. 首次启动时复制通用配置。已有配置则保留，不覆盖：

   ```powershell
   New-Item -ItemType Directory -Path data -Force | Out-Null
   if (-not (Test-Path -LiteralPath data/runtime.json)) {
     Copy-Item -LiteralPath config/runtime.example.json -Destination data/runtime.json
   }
   ```

4. 编辑本机 `data/runtime.json`：示例项目根目录为 `E:\AI`，每个项目使用独立子文件夹。没有 E 盘时，将 `projectRoot` 改成自己的绝对目录，例如 `"D:\\AIProjects"`。保持 `projectIntegration` 为 `cli`。可选项如下：

   | 配置项 | 作用 |
   | --- | --- |
   | `desktopProjectRegistration` | 自动向 Codex 桌面登记项目；示例默认关闭 |
   | `claudeDesktopAutoOpen` | 新项目自动在 Claude 桌面打开文件夹；示例默认开启 |
   | `codexExecutable` | 当 Codex 不在 PATH 中时，指定自己的官方 `codex.exe` 绝对路径 |

   首次信任文件夹需要本人在官方窗口确认。不要提交本机 `data/runtime.json`。

5. 执行 `npm start`，访问 `http://127.0.0.1:43118/`；也可以双击 `启动项目工作台.cmd`。窗口关闭后后台仍可运行。

`package.json` 保留 `private: true` 是为了防止误发到 npm，与 GitHub 仓库的公开状态无关。

## 归档、恢复与删除

在聊天菜单选择“归档”；在左侧“已归档聊天”里选择“恢复”。同一条工作台聊天用过两个助手时，一次操作分别处理它们关联的会话。

- **Codex 桌面会话**：调用官方归档／恢复入口，核对精确会话编号、原生状态与桌面目录。恢复由桌面自己的入口完成，避免仅改变 CLI 状态而留下旧界面。
- **Claude 已登记桌面的会话**：调用官方归档／恢复入口，原生对话文件保留在原位。
- **Claude 尚未登记桌面的会话**：使用工作台本地暂存，恢复时核验后放回原位。这种结果明确标为本地范围，不冒充桌面或云端归档。
- **删除聊天**：核验已关联的桌面入口和本地会话，完成后才移除工作台记录。官方端已经删除的会话也会独立核验；文件缺失、读取失败或同名标题不会单独被当作成功。
- **项目文件和其他聊天**：归档／恢复保留内容，删除聊天也保留项目文件。项目移除保留目录和聊天。项目改名仍只同步 CLI，不承诺桌面项目名即时更新。

同步会短暂操作桌面窗口，请暂勿操作鼠标、键盘或切换窗口；Esc 可中止。工作台逐个核验结果，只有全部通过才显示完成；部分失败会保留进度供重试。忙碌或等待批准的会话、身份不明、远程／独立工作树，以及可能影响其他聊天或定时任务的操作会停止。

本工具不会清空全局文件历史、其他备份，也不承诺清除所有云端副本。桌面界面升级后如不兼容，会保留未完成状态，不能保证永不失败。

## 数据与权限

项目内容位于自行选择的项目目录。工作台聊天、附件、状态和交接快照位于本机 `data/`；日志和临时文件位于 `work/`。这些目录、官方 CLI 登录目录、环境配置和测试文件均不属于发布内容。

本机保存不等于离线推理：发送任务后，官方 CLI 会按权限和账号设置将相关内容发送给模型服务。服务仅监听回环地址并检查同源请求与本机会话，请勿暴露到公网。项目外写入需要审批，工作台不绕过官方信任或操作批准。

同一原生会话仍被桌面或终端运行时，工作台会阻止重复续写。不要在多个入口同时编辑同一条原生会话。

## 兼容性

已在 Windows 环境验证 Codex／Claude 的聊天归档、恢复及两边联动。桌面同步依赖官方应用版本和当前会话状态；其他操作系统尚未完成整体运行验证。
